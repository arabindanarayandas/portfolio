How I built this website with AI, without writing a line of code

Every page on this site was coded by AI. Every decision about what goes on it was mine. Here is how that worked, including the technical details and the mistakes I caught.

Product owner: brief, content, evidence, every decision

The brief

I wanted a portfolio that shows proof, not claims: real numbers, real artwork, real chats, real people vouching for the work. I'm a product manager, not an engineer, and I set myself a rule: I would not write or edit any code. I would only describe what I wanted, supply the material, and judge the result.

How the work split

What I did

  • Set the goal and the audience: recruiters and product leaders
  • Told every story, by voice notes and messages
  • Supplied the evidence: game artwork, WhatsApp chats, campus photos, reports, videos
  • Checked every number and claim
  • Decided what to show and what to keep private
  • Set up the domain and GitHub, following step-by-step instructions

What the AI did

  • Designed the look and wrote all the HTML, CSS and JavaScript
  • Turned my stories into case studies, then rewrote on feedback
  • Processed images, video, audio and camera RAW photos
  • Built the charts, mock-ups, demo and animations
  • Tested every change on desktop, phone and dark mode
  • Published each change to the live site

The work ran as a loop: I described a change, the AI built it, took screenshots to check it, published it, and I reviewed it on my own phone.

I describe→AI builds→AI checks screenshots→AI publishes→I review

Five decisions that mattered

Proof over claims.

The first draft read like a resume. I asked for a review as a recruiter and as a product leader, then restructured around case studies with evidence: dated team chats, real game artwork, a signing photo and recommendations from my former managers.

Get every number right.

The team chats were dated August 2021, but the site said 500K users in 12 months. I checked: it was 18. I corrected it everywhere, including my resume. I also removed a number the AI had invented.

Protect what isn't mine to share.

Trumio is my current employer, so no client names and no real reports. Instead, the AI built mock-ups with made-up data, clearly labelled. Names and numbers in the chats are blurred. One IIT that turned us down stays unnamed.

Position myself honestly.

Invari is a side project, so I'm its product lead here, not its CEO. I credit my co-founder for the engineering and my former teams for what they built.

Design for the person reading.

A recruiter gives a portfolio about a minute. So: a link preview card, pictures on every case study, a resume one click away, and a contact form that asks why you're reaching out before it opens your email.

The technical details

The site is deliberately simple: plain files, no framework, no database, no build step. That makes it fast, free to host and easy to change.

PartWhat it is
PagesHand-written HTML, CSS and plain JavaScript. One file per page, about 3,300 lines in total.
HostingGitHub Pages, free. Every change is a commit to a public repository.
Domainauronara.com, bought from BigRock. Four DNS "A" records point it to GitHub, and a "www" record points to my GitHub address. GitHub issues the security certificate (HTTPS) automatically.
Clean addressesPages live in a /work folder, so links read /work/mio instead of mio.html. Old links redirect.
DesignOne typeface (Hanken Grotesk), one green accent, automatic dark mode, and layouts tested at phone width.
ImagesProcessed in Python with Pillow: cropping, sharpening logos, blurring names in chats, compressing photos. Camera RAW (.NEF) photos were converted with rawpy.
Video and audioffmpeg prepares the Invari film to start playing before it fully loads, and compressed the case study audio from 10.6 MB to 4 MB.
AnimationThe Mio card is an animated WebP built frame by frame in Python, panning across a high-resolution screenshot.
Resume and preview imageBoth are designed in HTML and rendered by a headless browser: the resume to a one-page PDF, the link preview to a 1200 × 630 image.
TestingPlaywright, a browser-automation tool, opens each page at desktop and phone sizes and in dark mode, clicks the buttons, and takes screenshots for review.

A few pieces of the actual code

The contact form that asks why you're getting in touch builds a pre-written email for each reason:

// Each option opens the visitor's email with a subject and a draft
var href = 'mailto:' + EMAIL
  + '?subject=' + encodeURIComponent(option.subject)
  + '&body='    + encodeURIComponent(option.body);

The Invari demo uses the same rule as the real product: a request is only as trustworthy as its weakest fix.

work/invari.htmlJavaScript
var min = Math.min.apply(null, fixes.map(function (f) { return f.confidence; }));
var blocked = min < scenario.threshold;   // e.g. 0.92 for payments

The LinkedIn and GitHub logos take on the site's colours automatically, including in dark mode, by using each logo as a stencil:

every pageCSS
.brand {
  background: currentColor;              /* the menu's text colour */
  mask: var(--m) center / contain no-repeat;  /* the logo shape */
}

What I learned

The bottleneck is no longer code. It's judgement.

The AI could build anything I described in minutes. The hard part was knowing what to build, what to cut, and what was true.

AI is confidently wrong in small ways.

An invented page count, a misleading thumbnail, a pop-up stuck in a corner. Each was easy to fix, but only because I looked.

Review it like a stranger would.

The biggest improvements came from asking "how does this look to a recruiter?" rather than "does this look nice?"

This is how I want to build products: AI does the making, and I own the decisions.
